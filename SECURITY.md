# Security Policy

## Supported Versions

Security fixes are intended for the current public release line of
Automation Platform.

Older development snapshots and historical phase tags may be retained for
traceability, but they should not be assumed to receive security fixes.

## Reporting a Vulnerability

Please do not disclose suspected vulnerabilities in a public issue before
the maintainers have had an opportunity to investigate and remediate them.

When GitHub private vulnerability reporting is enabled for this repository,
use that mechanism for security-sensitive reports.

A useful vulnerability report should include:

- the affected component or endpoint;
- the observed behavior;
- the expected behavior;
- reproducible steps when safe to provide;
- the potential security impact;
- relevant runtime and environment information; and
- any suggested mitigation, if known.

Do not include passwords, access tokens, private keys, production
connection strings, personal data, or other live credentials in a report.

## Security Reports Versus Ordinary Bugs

Use the private security-reporting mechanism for vulnerabilities that could
affect confidentiality, integrity, authorization, availability, credential
handling, or other security boundaries.

Ordinary functional defects that do not expose a security boundary may be
reported through the normal issue workflow after the repository is
published.

## Coordinated Disclosure

Please allow reasonable time for investigation and remediation before
public disclosure of a confirmed vulnerability.
